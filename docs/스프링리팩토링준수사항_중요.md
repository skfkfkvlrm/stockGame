# SchoolStock 스프링 부트 리팩토링 가이드라인 (SimpleSB Edition)

본 가이드는 기존 JDBC/MyBatis 프로젝트를 Spring Boot 3.x로 전환하며, **"최소한의 복잡도로 최대의 효율"**을 내는 SimpleSB 아키텍처 원칙을 준수하기 위한 실행 조약입니다.

## 0. SimpleSB 리팩토링 핵심 원칙
1. **Autoconfiguration 우선:** 불필요한 설정 파일(XML/Java Config)을 만들지 말고 스프링 부트가 제공하는 자동 설정을 최우선으로 사용합니다.
2. **Lean Layering:** 컨트롤러와 서비스는 얇게 유지하고, 비즈니스 로직은 최대한 서비스 단으로 몰아 응집도를 높입니다.
3. **불변 객체 우선:** DTO/VO는 고민하지 말고 무조건 Java 21 `record`를 사용하여 코드 다이어트를 실천합니다.

---

## 1. 환경 및 설정
* **Jakarta EE:** `jakarta.*` 패키지 사용을 강제합니다.
* **패키징:** JSP/JSTL 유지 및 톰캣 구동을 위해 `WAR` 패키징 방식을 유지합니다.
* **DB 설정:** `application.properties`에 아래 설정만으로 오라클/MyBatis 연동을 끝냅니다.
  ```properties
  mybatis.configuration.map-underscore-to-camel-case=true
  spring.datasource.hikari.maximum-pool-size=10
  ```

## 2. 컨트롤러 및 API (Presentation Layer)
* **@Controller:** JSP 페이지 이동이 필요한 경우 사용합니다.
* **@RestController:** AJAX 통신(현재가, 주문현황 등) 전용. JSON 응답은 메서드에서 객체를 바로 리턴합니다. (Gson 수동 파싱 삭제)
* **PRG 패턴:** 상태 변경(매수/매도/쿠폰구매 등) 후에는 `return "redirect:/main"`을 통해 중복 요청을 원천 차단합니다.
* **세션 주입:** `request.getSession()` 호출 대신 컨트롤러 메서드 인자에 `@SessionAttribute("student_id") String studentId`를 사용하여 깔끔하게 세션을 바인딩합니다.

## 3. 영속성 계층 (MyBatis Mapper)
* **인터페이스 중심:** 기존 구체 DAO 클래스(DBCP 로직 포함)를 삭제하고 `@Mapper` 인터페이스만 정의합니다.
* **데이터 방어 조약 (핵심):**
    * **쌍따옴표 별칭:** 모든 SELECT 쿼리에 `AS "name"`과 같이 소문자 별칭을 지정하여 대소문자 혼선을 방지합니다.
    * **Null/0 안전장치:** 정수형 데이터 조회 시 SQL 단에서 `NVL(SUM(profit), 0)` 등을 사용하여 런타임 NPE(NullPointerException)를 100% 방어합니다.
* **트랜잭션:** 수동 `commit/rollback` 코드를 걷어내고, 서비스 메서드 상단에 **`@Transactional`** 하나로 모든 원자성을 보장합니다.

## 4. 데이터 및 비즈니스 로직
* **Record DTO:** 모든 데이터 전달 객체는 아래와 같이 작성합니다.
  ```java
  public record OrderDTO(int orderNo, int stockNo, int amount, String state) {}
  ```
* **유효성 검증:** 컨트롤러 인자에 `@Valid`와 `@Min(1)` 등을 사용하여 수동 `if` 검증 로직을 제거합니다.
* **Switch Expressions:** 복잡한 `if-else` 대신 Java 21의 `switch` 문법으로 매칭 엔진 로직을 간결하게 작성합니다.

## 5. 예외 처리
* **Global Exception:** `@RestControllerAdvice` 하나를 만들어 모든 예외(SQL, Validation 등)를 중앙에서 가로채고 JSON 응답 객체를 반환하여 깔끔한 클라이언트 대응을 수행합니다.
